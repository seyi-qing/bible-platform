# v0.9 Release — Audio + Queue Infrastructure

This release adds the media-domain boundary and Redis-backed queues needed for production asynchronous work.

Queues cover audio processing, notifications, AI jobs, and search indexing. Heavy work belongs in workers rather than request handlers. NestJS documents BullMQ as its actively developed Redis-backed queue integration and supports distributed consumers. 

Audio is metadata-first. The current service deliberately returns `streamUrl: null` until a licensed CDN/object-storage integration is configured. That is intentional: we must not fabricate media URLs or accidentally redistribute copyrighted audio.
