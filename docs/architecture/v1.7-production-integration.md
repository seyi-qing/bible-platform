# v1.7 — Production Integration & Security Hardening

## Purpose

v1.7 tightens the v1.6 worker release without pretending the repository has passed a real dependency install in this offline environment.

## Changes

### API validation
- Zod failures now return HTTP 400 with a stable `VALIDATION_ERROR` contract.
- UUID route identifiers are validated before database access.
- Reading-plan mutations return 404 rather than silently returning an empty array when the target does not exist.

### Reading-plan authorization
- Adding days requires ownership.
- `dayNumber` cannot exceed `totalDays`.
- Progress cannot be written by a user who has not enrolled, unless they own the plan.
- Private plans cannot be joined by non-owners.

### Database pooling
`createDatabase()` now reuses a process-level PostgreSQL pool for the same resolved connection string. This prevents every service class from creating its own independent pool.

### Health checks
- `/api/v1/health/live` is liveness only.
- `/api/v1/health/ready` verifies PostgreSQL and Redis.
- `/api/v1/health` remains an alias for readiness.

Nest's Terminus model explicitly supports liveness/readiness checks and dependency health indicators. See the official NestJS health-check documentation. 

### API documentation
Swagger/OpenAPI is exposed at `/api/docs` so clients can inspect the versioned API contract during development/staging.

### Rate limiting
A Nest throttling guard is enabled as a baseline. It is deliberately documented as **per-process** until a Redis-backed throttler store is installed; horizontal deployments must not treat the in-memory limiter as a complete distributed abuse-control system.

### Worker reliability
BullMQ retry/backoff remains the source of truth for asynchronous retry behavior. Unrecoverable jobs should use `UnrecoverableError` rather than ordinary exceptions when retrying would be harmful.

## Release limitation

A real `pnpm install`, migration run, compile, integration test, E2E test, container boot, and production smoke test still need to run in a network-enabled CI environment. No fake lockfile is generated to hide that limitation.
