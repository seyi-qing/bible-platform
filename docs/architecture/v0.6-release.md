# v0.6 Release Notes

This release adds three user-facing domain foundations: reading plans, prayer journaling, and reading history.

## Design principles

1. **User ownership is enforced at the query boundary.** Every authenticated read/write is scoped to the authenticated subject.
2. **Plans store references, not copied Bible text.** A plan can therefore remain independent of a specific licensed text payload and resolve passages at reading time.
3. **Prayer entries are private by default.** Community sharing is intentionally a later, explicit feature rather than an accidental default.
4. **Reading history is product state, not analytics.** The history table should not be treated as a general telemetry store.
5. **Database evolution remains migration-driven.** Production deployments should apply reviewed, versioned migrations instead of creating or mutating schema during application startup.

## API surface

All routes below are under `/api/v1` and require an authenticated user.

| Domain | Endpoint | Purpose |
|---|---|---|
| Plans | `GET /plans` | List owned plans |
| Plans | `POST /plans` | Create plan |
| Plans | `PUT /plans/:id` | Update owned plan |
| Plans | `DELETE /plans/:id` | Delete owned plan |
| Plans | `GET /plans/:id/days` | Read plan days |
| Plans | `POST /plans/:id/days` | Add a day |
| Plans | `POST /plans/:id/enroll` | Enroll current user |
| Plans | `POST /plans/:id/progress` | Set completion state |
| Prayer | `GET /prayers` | List prayers |
| Prayer | `POST /prayers` | Create prayer |
| Prayer | `PUT /prayers/:id` | Update prayer |
| Prayer | `DELETE /prayers/:id` | Delete prayer |
| Prayer | `GET /prayers/:id/updates` | List prayer updates |
| Prayer | `POST /prayers/:id/updates` | Add prayer update |
| History | `GET /history` | Recent reading state |
| History | `POST /history` | Upsert reading progress |
