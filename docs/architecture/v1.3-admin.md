# v1.3 Admin and Moderation

## Boundary

The admin web app is an operator interface. It never grants itself authority. Every request goes to the API and is authenticated with a bearer access token; the API then checks the current user's role in PostgreSQL.

## Current operations

- Overview counts
- Recent users
- Role changes
- Report listing/filtering
- Report resolution/dismissal
- Audit log access

## Security rules

1. Never trust a client-side `isAdmin` flag.
2. Re-read privileged role state server-side.
3. Audit every privileged mutation.
4. Never expose password hashes, refresh-token hashes, secrets, private notes, prayer content, or AI private conversation data in the admin overview.
5. Add explicit permissions before expanding moderator/support capabilities.

## Next hardening

- CSRF strategy if browser cookies are introduced
- step-up authentication for destructive actions
- two-person approval for account deletion and role escalation
- pagination and cursor-based audit browsing
- immutable/append-only audit export
- feature-flag management
- queue/worker dashboard
