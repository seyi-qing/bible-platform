# v1.9 Attack & Failure Testing

## Purpose

v1.9 is a security and reliability regression layer. It does not claim that every production test has passed; it adds executable checks and release criteria that must be run in a network-enabled CI environment.

## Authorization matrix

For every user-owned resource, the expected behavior is:

| Actor | Target | Expected |
|---|---|---|
| Anonymous | Protected resource | 401 |
| User A | User A resource | Allow |
| User A | User B resource | 403 or intentionally indistinguishable 404 |
| User | Admin-only operation | 403 |
| Admin | Authorized admin operation | Allow |
| Any user | Missing object | 404 |

Object identifiers supplied by clients must never be trusted as proof of ownership.

## Failure classes

### Authentication
- malformed bearer tokens
- expired access tokens
- revoked sessions
- refresh-token replay
- concurrent refresh

### Authorization
- cross-user notes/highlights/bookmarks/history
- private reading plans
- private groups
- AI job ownership
- admin endpoints
- device ownership during sync

### Async processing
- duplicate job IDs
- provider timeouts
- retryable versus permanent errors
- worker restart during processing
- Redis outage
- database outage

### Input/resource abuse
- malformed JSON
- schema-invalid payloads
- oversized payloads
- pathological search queries
- repeated AI requests

## Executable smoke tests

After dependencies are installed and PostgreSQL/Redis/API are running:

```bash
pnpm test:integration
node tests/integration/unauthenticated-boundary.mjs
node tests/integration/failure-boundaries.mjs
pnpm test:e2e
```

These are smoke/regression checks, not a substitute for a penetration test.

## Release rule

A release is not marked PASS merely because the test source exists. The CI job must execute successfully against a real dependency installation and a clean database.
