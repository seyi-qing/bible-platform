# v1.8 — Full System Verification & Release Engineering

## Purpose

v1.8 is not a feature release. It establishes a repeatable release gate that exercises the system as a system: PostgreSQL, Redis, API, worker queues, web, migrations, authorization boundaries, and browser smoke tests.

## Verification layers

1. Static repository checks.
2. TypeScript type checking.
3. Workspace builds.
4. Fresh PostgreSQL migration application.
5. API authorization smoke tests.
6. API unit/security tests.
7. Web Playwright smoke tests.
8. Docker service health checks.

Nest recommends combining isolated tests with integration and end-to-end tests because e2e tests validate behavior closer to what a real user experiences. Playwright is used for browser-level verification. OWASP's API guidance makes authorization regression especially important because broken authorization remains a major API risk.

## Release rule

A release candidate is not considered production-ready when only source code compiles. The clean-database migration path, dependency installation, API startup, authorization tests, browser smoke tests, and service health checks must pass in CI.

## Known limitation

The repository currently does not ship a generated `pnpm-lock.yaml` because the previous build environment could not reach the package registry. CI intentionally does not pretend that a lockfile exists. Generate and commit the real lockfile before enabling frozen installs.
