# v1.1 Testing Strategy

The platform uses multiple test layers rather than relying on one end-to-end suite.

## Unit tests

Pure functions and domain logic are tested close to their packages. The Bible reference parser and request validation schemas are examples.

## API integration / E2E

NestJS supports isolated testing modules and HTTP-level end-to-end tests. API tests should cover authentication, authorization, persistence, sync, Bible retrieval and queue boundaries.

## Browser E2E

Playwright covers critical user journeys against a running web application. The initial smoke test verifies that the home page renders. As features stabilize, add journeys for reader navigation, search, login, study actions and plans.

## CI policy

Every pull request should run type checking, builds, unit tests and the critical browser suite. Full database/Redis integration tests should run against ephemeral CI services rather than developer machines.

## Test data

Never use real user data, private prayer entries, real authentication credentials, or production Bible-license credentials in tests.
