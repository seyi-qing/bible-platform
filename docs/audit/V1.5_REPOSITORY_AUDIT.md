# v1.5 Repository Audit

This release is an audit and hardening pass over the v1.4 deployment baseline. It is **not** a substitute for an external penetration test or production CI validation.

## Findings fixed

### High — refresh-token rotation race
Two simultaneous refresh requests could both observe the same token before either update completed. Rotation now uses a compare-and-swap update predicate containing the current token hash, revocation state, and expiry. Only one concurrent request can rotate the token successfully.

### High — sync note object ownership
Highlights, bookmarks and history checked ownership before mutation, but note upserts did not. A malicious client supplying another user's note UUID could reach the upsert path. Notes now check ownership before update/insert and reject cross-account object IDs.

### High — production database secret mismatch
PostgreSQL used a Docker secret while the API was given a placeholder password through `DATABASE_URL`. The database client now supports `DATABASE_PASSWORD_FILE`; API and worker services mount the same secret.

### Medium — unsafe implicit AI model default
The API previously supplied an implicit model identifier. AI generation now requires `AI_MODEL` whenever an AI API key is configured, preventing an invalid model from being silently used in production.

### Medium — startup environment validation
Required production configuration is now validated before NestJS bootstraps. Production also requires the internal indexing/admin token.

### Low — Next.js lint command compatibility
The web package no longer calls the removed `next lint` command. TypeScript checking is currently the package lint gate until the repository adopts a shared ESLint configuration.

## Security review scope

The audit focuses on authentication, object-level authorization, function-level authorization, resource consumption, security configuration, secrets, and third-party API boundaries. These areas map directly to the OWASP API Security Top 10, including Broken Object Level Authorization, Broken Authentication, Broken Function Level Authorization, Unrestricted Resource Consumption, Security Misconfiguration, and Unsafe Consumption of APIs.

## Validation limitation

The current build environment does not have pnpm dependencies installed and cannot reach the npm registry. A fresh dependency installation/build therefore could not be executed in this environment. The archive is statically audited and ZIP-integrity checked, but CI must still run the full install, typecheck, tests, migrations, security scans, and deployment smoke tests.
