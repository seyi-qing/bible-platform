# v1.2 Authorization Regression Plan

This pass focuses on OWASP API Security risks that matter most to this application, especially broken object-level authorization (BOLA), broken function-level authorization, excessive data exposure and unrestricted resource consumption.

## Required regression cases

1. User A cannot read/update/delete User B notes, highlights, bookmarks or history.
2. User A cannot push a sync operation whose `entityId` belongs to User B.
3. A refresh token cannot be used after rotation/revocation.
4. Non-admin users receive `403` from `/api/v1/admin/*`.
5. Anonymous users cannot access authenticated community, AI, sync or notification resources.
6. A non-member cannot read or write private-group content.
7. Notification reads are scoped to the authenticated user's notification ID.
8. AI conversation/message retrieval is scoped to the owning user.
9. Search/indexing endpoints cannot be used to exfiltrate unlicensed or unauthorized Bible text.
10. API responses must use explicit DTOs rather than serializing password hashes, refresh-token hashes or internal secrets.

## Test environments

- Unit: Vitest, no external services.
- Integration: disposable PostgreSQL + Redis.
- E2E: API process + PostgreSQL + Redis + Playwright browser.
- Never run destructive integration tests against a developer's normal database.

## Release gate

A production release fails if any ownership, authentication, authorization, secret-exposure or migration test fails.
